# 01｜框架全景与设计顺序

## 核心认识

在这次学习中，可以把三层职责这样理解：**LangGraph 管执行图、状态与检查点；LangChain 管模型、消息、工具与 Agent 循环；Deep Agents 在其上装配文件、规划、Skills、子 Agent 等能力。** 这是理解项目的工作模型，不是说每层只能做这些事。

一个 Agent 的质量主要取决于：任务定义、可用信息、可执行动作、状态和记忆范围、验证与权限。AI 可以协助写实现，但这些选择需要人根据业务做出，并通过实际运行核对。

## 设计顺序

1. **定义任务**：输入是什么，最终产物是什么，哪些限制不可违反。
2. **定义验收**：什么证据说明产物有效；格式、事实、业务可行性分别怎么检查。
3. **提供能力**：原子动作做成 Tool；重复流程做成 Skill；必要背景和偏好放入 Memory；资料和产物安排到合适 Backend。
4. **控制过程**：多步骤任务用规划跟踪；复杂研究可委派子 Agent；敏感动作在执行前审核。
5. **观察结果**：检查工具轨迹、文件内容、状态和真实模型表现，不只看最终自然语言回复。

## 五种常混淆的对象

| 对象 | 回答的问题 | 例子 |
| --- | --- | --- |
| Tool | 能做什么具体动作？ | `save_plan`、`read_plan`、`check_plan` |
| Skill | 这类任务怎样组合动作？ | 先提取目标，再保存、读回、检查计划 |
| Memory | 哪些信息要在未来会话继续使用？ | 用户明确要求记住的语言和格式 |
| Backend | 文件通过什么路径访问，存在哪里？ | `FilesystemBackend`、`StateBackend`、`StoreBackend` |
| Middleware | 在 Agent 运行中插入什么通用行为？ | `TodoListMiddleware`、`MemoryMiddleware`、`RubricMiddleware` |

Tool 与 Skill 解决不同问题：Tool 是一次可调用动作，Skill 是可复用的做事方法。Memory 是内容与作用域，Backend 是访问和存储机制。Backend 可承载 Memory 和 Skill 文件，但不会自动决定哪些信息值得保存。

## 需要避免的推断

- 配好了 Backend，不代表 Agent 会自动保存计划。
- 注册了 Tool，不代表真实模型一定会调用。
- Todo 标为完成，不代表产物存在或合格。
- 有最终回答，不代表通过验收。

## 自测问题

面对“帮我做两周学习计划”，先说出产物和验收，再分别指出需要哪些 Tool、Skill、Memory、Backend。若一个能力没有明确职责，先不要加进架构。
