# 02｜规划中间件：跟踪步骤，不代替交付

## 何时使用

任务有多个依赖步骤、会产生文件或需要中途验证时，规划有助于 Agent 明确当前要做什么。单步简单查询通常不需要单独维护 Todo。

在本项目锁定的 Deep Agents 0.7.8 实验中，显式配置 `TodoListMiddleware()` 后出现 `write_todos`；移除后工具注册清单不再包含它。不要把“提示词要求规划”和“运行时提供规划工具”混为一谈。不同版本的默认行为应重新确认。

## 运行机制

`write_todos` 一次提交的是**完整任务清单**，后一次调用可整体替换前一次清单。状态常见为 `pending`、`in_progress`、`completed`。待办应描述实际工作步骤和产物，不要把“更新待办”本身写成任务。

对“保存计划 → 读回 → 检查”这类依赖链，应等前一个工具结果成功后再执行下一个。模型同一轮并行发出相互依赖的调用，可能出现读取先于写入的时序问题。

## 如何判断完成

至少分三层检查：

1. **过程状态**：Todo 是否都到 `completed`，失败项有没有被错误标为完成。
2. **产物状态**：文件是否真正保存，能否读回，读回内容是否是这次生成的版本。
3. **内容质量**：结构、事实和可行性是否满足用户目标。

Task 8 的一次真实运行生成了计划文件且结构检查返回 `ok=true`，但最后一项 Todo 仍为 `in_progress`，因此严格验收没有通过。这个例子说明“文件已生成”和“Agent 全部步骤已完成”是不同结论。

## 常见误区

- **“模型说完成了”**：这是文本，不是状态更新。查看实际 `write_todos` 调用和最终 state。
- **“Todo 完成就交付”**：还要检查文件和内容。
- **“离线实验通过就等于模型会自主规划”**：预设模型只验证机制；自主行为要看真实模型轨迹。
- **“没有 `todos` 键一定没规划”**：还要看版本、图状态定义、流事件与注册工具；Task 1 曾遇到结果 state 与课程预期不一致。

## 自测问题

如果 Agent 已保存文件并回答“完成”，但 `todos` 仍有 `in_progress`，你会怎样记录这次运行？哪些检查属于结构验证，哪些需要人工判断？
