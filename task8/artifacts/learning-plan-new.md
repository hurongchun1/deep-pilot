# pandas CSV 清洗两周行动计划

## 任务目标

- 学习目标：在具备 Python 基础的前提下，能用 pandas 独立完成一份 CSV 的完整清洗流程（读取 → 结构摸底 → 缺失值 / 重复 / 文本 / 类型与日期 / 异常值处理 → 导出）。
- 最终交付两项产物：
  1. 一个可执行的清洗脚本：输入原始 CSV，输出清洗后的 CSV（建议命名 `clean_csv.py`）。
  2. 一份前后数据对照：清洗规则清单 + 关键指标前后对照 + 抽样行对照（建议命名 `before_after_report.md`，指标可另存 `metrics.csv`）。
- 附带产物（为保证可复现）：`cleaning_rules.md`（规则表）、`README.md`（安装与运行说明）、`retro.md`（复盘）。

## 行动步骤

### 阶段一：理解与准备（第 1–3 天）

- 第 1 天（60 分钟）：环境与首次读取。确认 Python / pandas 版本可运行；把选定的原始 CSV 放到工作目录；用 `read_csv` 读入，查看 `shape`、`head()`、`dtypes`、`info()`。
  - 产物：`day01_load.ipynb`，含最少 5 行读取与查看代码。
  - 完成标准：能不看笔记复述每行代码作用，并写出“这份数据有多少行多少列、哪几列类型不对”。
- 第 2 天：数据质量摸底。逐列统计缺失数量与比例、唯一值个数、3–5 个样例值，记录疑似问题（空值、重复、空格/大小写不一致、日期格式混乱、数值越界）。
  - 产物：`data_profile.md`，按列一行的清单。
  - 完成标准：每一列都有一个明确判定（“无需处理”或“待清洗”），并附证据（数量或样例）。
- 第 3 天：定义清洗规则与目标表结构。为每个待清洗项写：列名、问题、处理动作、理由、预估影响行数；同时确定输出保留哪些列、每列目标类型。
  - 产物：`cleaning_rules.md`（规则表）。
  - 完成标准：规则表覆盖第 2 天清单里全部“待清洗”项，每条都有可判断的条件（例如“`amount` 为空则删除该行”），不留“看着办”的条目。

### 阶段二：核心技能练习（第 4–9 天，每项技能当天产出一个可复用函数）

- 第 4 天：缺失值处理。`isna().sum()`、`dropna` / `fillna`（均值、中位数、众数、前向填充）的适用场景与副作用。
  - 产物：`funcs.py` 中的 `handle_missing(df)` + 当天练习记录。
  - 完成标准：能说明每种填充方式会改变什么，并对应到 `cleaning_rules.md` 中的具体条目。
- 第 5 天：重复与主键。`duplicated()` / `drop_duplicates()`，确定业务去重键与保留策略（保留首条/最新）。
  - 产物：`dedupe(df)`。
  - 完成标准：去重后行数变化能被解释（删了多少、为什么删这些）。
- 第 6 天：文本与列名清理。`str.strip()`、`str.replace()`、`str.lower()`、正则提取、`rename(columns=...)`。
  - 产物：`clean_text(df)`。
  - 完成标准：同一类别值不再因空格/大小写被算成两类（用 `nunique()` 前后对比证明）。
- 第 7 天：类型与日期。`astype`、`to_numeric(errors='coerce')`、`to_datetime`、统一日期输出格式；记录转换失败产生的空值数量。
  - 产物：`fix_types(df)`。
  - 完成标准：目标列类型全部正确，转换失败项数量已记录且有处理决定。
- 第 8 天：异常值与筛选。`describe()`、分位数 / IQR 或业务阈值识别异常值，`loc` 条件筛选，派生必要新列。
  - 产物：`handle_outliers(df)` + 规则说明（阈值写进 `cleaning_rules.md`）。
  - 完成标准：异常值判定有可复现的数值标准，不靠肉眼挑行。
- 第 9 天：串成管道。把上述函数按顺序组成 `clean(df)`，跑通全量数据。
  - 产物：`clean_pipeline.ipynb`，一条调用完成全部清洗。
  - 完成标准：无报错跑完，输出行数/列数与预期一致，且与分步执行结果相同。

### 阶段三：脚本化与交付物（第 10–12 天）

- 第 10 天：脚本化。把管道写成 `clean_csv.py`：命令行参数（`--input` / `--output`）或固定路径、`if __name__ == "__main__"` 入口、运行时打印日志（读取行数、各步删除行数、输出行数）。
  - 产物：`clean_csv.py` 第一版。
  - 完成标准：`python clean_csv.py --input raw.csv --output clean.csv` 能一次跑通并生成文件。
- 第 11 天：做前后对照。统计清洗前后各项指标（行数、列数、缺失值总数与比率、重复行数、类型错误数、数值异常数），并抽取 5 行做逐字段前后对照。
  - 产物：`before_after_report.md` + `metrics.csv`。
  - 完成标准：表中每个数字都能在脚本日志或 notebook 输出里找到出处，无手填估算值。
- 第 12 天：边界测试。用 4 个用例测脚本：空文件、缺列、整列为空、编码差异（UTF-8 / GBK）。
  - 产物：`test_notes.md`（用例、输入、输出、结论）。
  - 完成标准：异常输入不崩溃，给出能看懂的错误提示；正常输入结果不变。

### 阶段四：复盘与验收（第 13–14 天）

- 第 13 天：可复现性检验。在新目录（或干净环境）按 README 从安装到产出结果完整走一遍，补齐 `README.md`（安装、运行命令、规则说明、输出文件说明）。
  - 产物：`README.md`。
  - 完成标准：不看旧笔记、不猜参数，15 分钟内能跑出清洗结果。
- 第 14 天：复盘与打包。写 `retro.md`：最常用的 5 个 pandas 操作、仍不确定的 3 个点、下一步方向；按“验收标准”逐条自查并勾选。
  - 产物：`retro.md` + 整理好的交付目录。
  - 完成标准：7 条验收标准逐条有“通过 / 未通过 + 原因”的结论。

## 验收标准

## 风险与调整

- 每日 60 分钟被挤占：若连续 2 天未完成当日任务，切换到最小版路径——只保留第 1、2、3、4、5、9、10、11、14 天内容，优先保两项交付物，文本清理与异常值处理降为“会用默认做法即可”。

- 某技能点超时：把该技能压缩到“会用默认参数 + 知道 2 个常用选项”，细节列入 `retro.md` 的后续学习清单，不阻塞主线。
- 命令行参数不熟（第 10 天）：先硬编码路径跑通，第 12 天再补 `argparse`；验收第 2 条相应改为记录“固定命令 + 修改路径说明”。

- 数据量过大导致单次运行超时：先抽 1000 行子集开发调试，最后一次跑全量，并在报告中注明数据规模。
