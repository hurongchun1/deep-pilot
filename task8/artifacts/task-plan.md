# pandas 清洗 CSV 两周学习计划

## 任务目标

在已有 Python 基础之上，用两周、每天 1 小时学会用 pandas 清洗 CSV 数据，最终交付两项成果：

1. 一个可重复运行的数据清洗脚本（输入原始 CSV，输出清洗后的 CSV）；
2. 一份清洗前后数据对照（行数、列数、缺失值、数据类型、重复行等指标及典型样例对比）。

## 已知条件

用户明确给出：

- 起点：具备 Python 基础（变量、函数、循环等），pandas 经验未说明。
- 时长：两周，每天 1 小时，合计约 14 小时。
- 学习主题：使用 pandas 清洗 CSV。
- 交付物：清洗脚本 + 前后数据对照。

以下为建议假设（非用户原话，可按实际调整）：

- 建议每天 1 小时拆为 45 分钟学习与练习 + 15 分钟记录当天产出。
- 建议以「小步练习 + 逐日累积到脚本」的方式推进，避免最后几天才动手写代码。
- 建议使用一份真实或接近真实的小型 CSV（100~10000 行量级）作为全程练习数据，避免每天换数据集导致脚本无法沉淀。
- 建议环境为本地 Python 3.x + pandas，在命令行或 Jupyter Notebook 中运行。

## 行动步骤

以下按相对时间安排，第 1 天为开始学习的第一天。每日产物建议放在同一项目目录下（如 `csv_clean/`），便于累积。

### 第 1 周：基础操作与常用清洗动作

**第 1 天｜环境准备与数据探查**
- 动作：安装/确认 pandas 可用；把练习 CSV 放入项目目录；用 `pd.read_csv` 读入，打印 `head()`、`shape`、`info()`、`dtypes`。
- 产物：可运行的读取脚本片段（`explore.py` 或 notebook 首个单元）+ 一页数据探查记录（多少行多少列、各列含义、看到的问题）。
- 完成标准：能独立读入文件并说清这份数据「有哪些脏」。

**第 2 天｜DataFrame 基础操作**
- 动作：练习选择列、切片、`loc`/`iloc`、布尔筛选、`rename`、列顺序调整。
- 产物：5~8 条可运行的筛选/取列示例代码。
- 完成标准：能按条件取出目标行子集，并解释每条代码作用。

**第 3 天｜缺失值处理**
- 动作：`isna().sum()` 统计缺失；练习 `dropna`（按行/按列/阈值）与 `fillna`（固定值、均值、前向填充）。
- 产物：针对练习数据的缺失值统计表 + 一段带取舍理由的填充代码。
- 完成标准：能说明每列缺失为什么删除或填充，而非盲目 `dropna()`。

**第 4 天｜重复值与数据类型**
- 动作：`duplicated().sum()`、`drop_duplicates`（按子集/保留策略）；`astype`、`to_numeric(errors="coerce")`、`to_datetime`。
- 产物：去重前后行数记录 + 类型转换代码（含转换失败行的处理方式）。
- 完成标准：去重与类型转换后无异常报错，且能报出被转换坏值的行数。

**第 5 天｜字符串清洗**
- 动作：`str.strip`、`str.lower/upper`、`str.replace`、`str.contains`、必要的正则提取（如从混合文本提取数字或日期）。
- 产物：文本列清洗函数片段（如统一去除空白与大小写、拆出一列新字段）。
- 完成标准：同一类的文本脏值（前后空格、大小写不一致、单位混写）被统一。

**第 6 天｜列与行级整理**
- 动作：列重命名统一风格、删除无用列、`query`/条件过滤非法行、必要时的 `apply` 与自定义函数。
- 产物：一份「保留哪些列、丢弃哪些行及理由」的清单 + 对应代码。
- 完成标准：清洗后列名含义清晰、无整列空值的冗余列。

**第 7 天｜第一周复盘与小整合**
- 动作：把第 1~6 天的片段按顺序装配成一个可顺序执行的脚本草稿；对练习数据跑一次并记录前后行数、列数。
- 产物：`clean_draft.py` + 第一版前后指标对照（行数、列数、缺失值总数、重复行数）。
- 完成标准：脚本从头跑到尾不中断，指标能对上（清洗后行数 = 原始行数 − 删除行数）。

### 第 2 周：校验、函数化与交付

**第 8 天｜异常值与范围校验**
- 动作：`describe()` 看分布；用分位数或固定阈值识别离群值；`clip` 或标脏；对日期、枚举类字段做取值校验。
- 产物：异常值清单（哪些列、多少条、判定规则）+ 处理代码。
- 完成标准：每条异常规则都能说出业务含义，处理结果可复现。

**第 9 天｜分组聚合与交叉核对**
- 动作：`groupby` + `agg` 做汇总核对；如需多表则练习 `merge`（连接键、连接方式、行数变化）。
- 产物：按关键维度（如类别、日期）的汇总表，用于辅助判断清洗是否合理。
- 完成标准：能解释清洗后汇总数据与原始数据量级差异的来源。

**第 10 天｜脚本函数化**
- 动作：把流程封装为 `clean_data(df)`（及必要的辅助函数），输入输出路径参数化，加 `if __name__ == "__main__":` 入口。
- 产物：`clean.py`（可传参运行：原始文件路径、输出路径）。
- 完成标准：更换输入文件名即可重跑，无需改代码内部逻辑。

**第 11 天｜日志与清洗指标**
- 动作：在脚本中记录每一步的行数变化、各列缺失值、去重数量、类型转换失败数；输出一份清洗日志或指标表（`clean_summary.csv`）。
- 产物：自动生成的清洗指标表 + 控制台日志。
- 完成标准：不打开数据也能从指标表看出每一步做了什么。

**第 12 天｜前后数据对照交付物**
- 动作：导出清洗后 CSV；生成对照报告（原始 vs 清洗后：行数、列数、缺失值、dtype 变化、重复行数），并抓 2~3 条典型记录做清洗前后逐字段对比。
- 产物：`cleaned.csv` + `before_after_report.md`（或含对照表的文件）。
- 完成标准：对照报告中每个指标都能由脚本输出复现，抽样的样例确实体现了清洗效果。

**第 13 天｜端到端演练与边界情况**
- 动作：用脚本重跑全流程；测试边界：中文/非 UTF-8 编码、空文件或全空列、日期格式混杂、大文件读取性能（如需要）。
- 产物：问题与修复记录（问题现象、原因、改法）。
- 完成标准：至少覆盖 2 个边界场景，重跑结果与第 12 天一致。

**第 14 天｜整理交付与复盘**
- 动作：补齐 README（用途、运行方法、参数说明、依赖）；确认脚本注释清晰；整理最终对照报告；写一份复盘清单（已会哪些操作、仍不熟的、后续想扩展的方向）。
- 产物：交付包 = `clean.py` + `cleaned.csv` + `before_after_report.md` + `clean_summary.csv` + `README.md` + 复盘笔记。
- 完成标准：他人按 README 即可在同类 CSV 上跑通脚本；对照报告与脚本输出一致。

### 时间安排建议

- 第 7 天与第 14 天各留出整合/复盘时间，不新增知识点。

## 验收标准

目标层面（结束时应当成立）：

1. 存在一个脚本，输入原始 CSV 即可输出清洗后 CSV，且在第 12、13 天两次运行结果一致。
2. 存在一份清洗前后对照材料，包含行数、列数、缺失值、重复行、dtype 变化的量化对比，以及至少 2 条记录的逐字段样例对比。
3. README 能让他人独立复现运行。
4. 能对着代码说明每一步为什么这样清洗（而非只调用了函数）。

区分说明：以上为验收条件定义，尚未产生任何实际运行结果；计划本身不代表任务已完成。实际完成情况需以第 14 天整理出的交付文件为准。

## 风险与调整

- 时间风险：每天 1 小时偏紧，若基础操作（第 2~5 天）超时，可把第 9 天的分组聚合降为选做，把时间让给脚本函数化与对照报告。
- 数据风险：练习数据未提供，若始终没有真实 CSV，可自造一份含缺失、重复、脏文本的小数据集（第 1 天完成），这不影响学习目标，但需要在交付说明中注明数据为示例。
- 范围风险：如果实际数据需要多表关联、大规模文件或数据库读取，两周内难以覆盖；建议把 `merge`、分块读取列为选做，并在复盘中列为后续扩展方向。
- 质量风险：只写 `dropna()`/`fillna()` 而不记录理由，会导致对照报告说不清「为什么变少」。缓解方式是第 3、11 天强制产出统计与理由清单。
- 触发调整条件：若第 7 天脚本草稿仍无法端到端跑通，第 8~9 天的校验内容缩减为「仅保留日期与数值范围校验」。
