# 两周 pandas CSV 清洗学习计划

## 任务目标

在 14 天内，用每天 1 小时（合计约 14 小时）把已有的 Python 基础延伸到「用 pandas 清洗 CSV」这一具体能力上，最终交付两个可检查的成果：

1. **清洗脚本**：一个可复用的 Python 脚本（建议命名 `clean_data.py`），输入原始 CSV、输出清洗后 CSV，清洗规则以代码显式表达（缺失值、重复行、类型、字符串格式等），并带有基本的运行日志/打印统计。
2. **前后数据对照**：一份对照材料（建议 `comparison.md` 或在脚本中打印并保存为 `comparison.csv`），至少包含清洗前后的行数/列数、各列缺失率、重复行数、关键列数据类型、以及若干样例行的前后对比。

目标不是「学完 pandas 全部 API」，而是「能独立写出并解释一个针对某份具体 CSV 的清洗脚本」。

## 已知条件

用户明确给出：

- 起点：具备 Python 基础（能读写变量、循环、函数、导入模块这一层级；具体深度待确认）。
- 周期：两周，即 14 天。
- 每日投入：1 小时。
- 学习对象：pandas 清洗 CSV。
- 最终产物：清洗脚本 + 前后数据对照。

补充说明（建议，非用户提出）：

- 建议每天固定时间块结构：约 10 分钟看资料、35 分钟动手敲代码、15 分钟记录当日结论与遗留问题。

## 行动步骤

### 第一阶段：环境与读取（第 1–2 天）

**第 1 天｜跑通环境与最小读取**

- 动作：安装/确认 pandas 可用；用 `pd.read_csv()` 读取目标 CSV；用 `df.shape`、`df.head()`、`df.info()`、`df.dtypes` 观察数据；把「这份数据有哪些列、哪些列看起来有问题」写成 5–8 条清单。
- 产物：`notes-day01.md`（数据概况 + 问题清单初稿）、`explore.py`（读取与查看的最小脚本）。
- 完成标准：能不看教程独立写出读取 + 查看的 4 行代码，并能说出 `info()` 输出里每个字段的含义。
- 依赖：无。

**第 2 天｜定位与切片**

- 动作：练习 `loc` / `iloc`、列选择与重命名（`rename`、统一列名为小写下划线）、布尔筛选（如「某列缺失的行」）。
- 产物：`explore.py` 增补筛选片段；笔记中记录 3 个真实筛选例子（都基于自己的 CSV）。
- 完成标准：能写出「选出 A 列为空且 B 列大于某值的行」这类复合条件。
- 依赖：第 1 天。

### 第二阶段：单类清洗动作（第 3–6 天）

**第 3 天｜缺失值**

- 动作：统计缺失（`isna().sum()`、缺失率）；练习 `dropna()`（含 `subset`、`how`、`thresh`）与 `fillna()`（常数、均值/中位数、前向填充）；对每一列判断「该删还是该填」。
- 产物：笔记中的「逐列缺失处理决策表」（列名 / 缺失率 / 处理方式 / 理由）。
- 完成标准：决策表覆盖 CSV 中所有存在缺失的列，且每条决策能说出理由。
- 依赖：第 2 天。

**第 4 天｜字符串与文本规范**

- 动作：`str.strip()`、`str.replace()`、`str.lower()`、`str.contains()`；处理首尾空格、全角/半角、单位混入（如「1,200元」）、枚举值大小写不一致。
- 产物：`notes-day04.md` 中记录每类脏文本的「清洗前 → 清洗后」实例，每个实例一行。
- 完成标准：至少 3 类字符串问题被实际修复，且能在 `value_counts()` 里看到修复效果。
- 依赖：第 2 天。

**第 5 天｜类型转换与重复行**

- 动作：`to_numeric(..., errors='coerce')`、`to_datetime(..., errors='coerce')`；理解转换失败会产生什么；`duplicated()` 统计与 `drop_duplicates()`（含 `subset`、`keep`）。
- 产物：笔记中的「类型转换前后对照」（列名 / 原 dtype / 新 dtype / 转换失败条数）。
- 完成标准：所有数值/日期列均为正确类型，并能解释每条 `coerce` 产生的 NaN 是数据问题还是格式问题。
- 依赖：第 3 天（需处理转换产生的缺失）。

**第 6 天｜整合小练习**

- 动作：把第 3–5 天动作按顺序串成一个脚本草稿 `clean_draft.py`，对同一 CSV 端到端跑一遍，记录行数变化。
- 产物：`clean_draft.py`（可运行）、`notes-day06.md`（行数变化链：清洗前 → 去缺失后 → 去重后）。
- 完成标准：脚本一次运行无报错，输出一份中间结果 CSV。
- 依赖：第 3、4、5 天。

### 第三阶段：校验、异常值与脚本化（第 7–10 天）

**第 7 天｜缓冲与复盘**

- 动作：不引入新知识；回看前 6 天笔记，补齐未完成的练习，整理「已掌握 / 半懂 / 未懂」三栏清单，据此微调后半程。
- 产物：`notes-day07.md`（三栏清单 + 后半程调整点）。
- 完成标准：明确列出至少 1 个需要额外补练的知识点。
- 依赖：第 1–6 天。

**第 8 天｜异常值与取值校验**

- 动作：`describe()`、分位数、`between()`、业务取值区间检查；识别离群值与非法取值（如年龄 999、日期在 1900 年前）；决定保留/截断/置空。
- 产物：笔记中的「异常值清单」（列 / 异常样例 / 判断依据 / 处理方式）。
- 完成标准：每条处理都写明依据（统计阈值或业务规则），不凭感觉删数据。
- 依赖：第 5 天。

**第 9 天｜聚合核对与清洗效果初验**

- 动作：用 `groupby()` + `agg()` 做少量聚合（如按类别求均值、计数），对比清洗前后的聚合结果差异，判断清洗是否改变了分布。
- 产物：笔记中一张 2–3 行的「清洗前/清洗后聚合对比」小表。
- 完成标准：能指出至少一处清洗导致的分布变化，并说明该变化是否符合预期。
- 依赖：第 8 天。

**第 10 天｜脚本结构与复用设计**

- 动作：把清洗逻辑拆成函数（读入、清洗、校验、导出各一个）；用 `argparse` 或文件顶部常量让输入/输出路径可配；加 `print`/`logging` 输出关键统计；处理「文件不存在」「必需列缺失」两类错误。
- 产物：`clean_data.py` 函数骨架（未必要完全跑通）+ 一页设计说明（函数职责分工）。
- 完成标准：函数边界清楚，明确「哪一步在哪里发生」。
- 依赖：第 6、9 天。

### 第四阶段：交付物（第 11–14 天）

**第 11 天｜完成清洗脚本**

- 动作：实现第 10 天骨架的全部函数，跑通完整输入→输出；确保脚本对同一输入可重复运行、结果一致。
- 产物：可运行的 `clean_data.py`、输出文件 `cleaned_data.csv`。
- 完成标准：命令行一条命令即可从原始 CSV 生成清洗后 CSV，无人工干预。
- 依赖：第 10 天。

**第 12 天｜生成前后对照**

- 动作：在脚本中增加对照统计（行数、列数、各列缺失数/缺失率、重复行数、各列 dtype 变化、清洗前后样例行）；导出为 `comparison.csv`，并整理成 `comparison.md` 叙述版。
- 产物：`comparison.csv`、`comparison.md`（含前后表格 + 3 条以内结论）。
- 完成标准：对照材料覆盖上述 6 类指标，且每个数字都能由脚本重新生成。
- 依赖：第 11 天。

**第 13 天｜边界测试与修补**

- 动作：构造 2–3 个小测试样本（空文件、缺列、脏值极端组合），验证脚本行为符合预期；修补崩溃点与静默错误。
- 产物：`edge_cases/` 测试样本 + 笔记中的「测试结果表」（用例 / 期望 / 实际 / 是否通过）。
- 完成标准：脚本在所有测试样本上不崩溃，或对无法处理的情况给出明确错误提示。
- 依赖：第 11、12 天。

**第 14 天｜整理与自交付**

- 动作：整理目录结构；补 `README.md`（用途、运行方式、清洗规则清单、已知限制）；逐条对照「验收标准」自检；写下 3 条最想继续深入的方向。
- 产物：完整交付目录（`clean_data.py`、`comparison.csv`/`.md`、`README.md`、`notes-*.md`、`edge_cases/`）。
- 完成标准：他人按 README 能复现你的运行结果。
- 依赖：第 11–13 天。

## 验收标准

以下为可检查条件，「期望」与「实际达成」需分开记录，14 天结束时逐条打勾：

1. `clean_data.py` 能在命令行一条命令从原始 CSV 生成清洗后 CSV，且重复运行结果一致。
2. 脚本以代码形式显式处理了至少 4 类问题：缺失值、重复行、类型转换、字符串格式（异常值处理可选但建议）。
3. `comparison.csv`/`comparison.md` 覆盖：行数与列数变化、各列缺失率、重复行数、关键列 dtype 变化、清洗前后样例行对照。
4. 每条清洗规则都能说出理由，并与笔记中的决策表对应。
5. 至少 2 个边界测试样本通过（不崩溃或给出明确提示）。
6. `README.md` 中他人可依描述复现运行。
7. 能脱离笔记、口头讲清「这份数据脏在哪、我怎么处理的、处理后变了多少」。

注意：本计划只描述应达成的状态，不代表任何一步已经完成；实际结果需在第 14 天自检时据实填写。

## 风险与调整

- **时间不足（最常见）**：若某天 1 小时无法完成当日动作，不要挤占次日内容；把未完成部分推入第 7 天缓冲日，仍不足则删减第 8–9 天（异常值与聚合校验属可裁剪项），但**保留第 11–14 天的交付阶段**。
- **数据未定**：若第 1 天前拿不到真实 CSV，先用 pandas 文档或公开示例数据练手，第 3 天前必须锁定真实数据，否则「前后对照」会失去意义。
- **卡在 API 记忆上**：不要背参数，改为在笔记里维护「常用操作 → 代码片段」速查表；卡超过 15 分钟就记为遗留问题并在第 7 天集中解决。
- **脚本越写越乱**：若第 11 天发现骨架无法承载逻辑，回头砍规则而不是加规则——宁可 4 条稳定规则，不要 8 条半成品。
- **清洗把数据洗没了**：若清洗后行数下降超过心理预期（例如超过一半），先停下核对删除条件，把「删行」改为「置 NaN 并标记」，避免不可逆损失。
- **调整触发条件**：连续 3 天未达成当日完成标准，视作进度风险，触发一次计划重排（压缩第三阶段、保留交付物）。
