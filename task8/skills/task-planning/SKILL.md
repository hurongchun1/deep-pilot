# 通用任务规划方法

1. 从用户消息提取目标、预期产物、可用时间、截止条件、资源与限制。目标本身不明确时先询问；其他缺失项可以列为待确认，并说明建议基于哪些假设。
2. 读取本 Skill 的 `references/plan-outline.md`。用户提供的条件通常足够；需要本地补充材料时，先调用 `list_sources`，只读取相关文件。不要把学习案例的时间限制或旧产品发布规则用于无关任务。
3. 使用 `write_todos` 跟踪理解需求、拆解步骤、保存和检查。按先后依赖拆解行动，写清每一步的产物、相对时间及完成标准；未知负责人写为待确认。
4. 把已知条件、建议、待确认事项分开。用户没有提供开始日期时使用“第 1 天”“第 1 周”等相对安排。不要编造预算、姓名或已完成结果。
5. 使用 `save_plan` 保存，再用 `read_plan` 读回，最后用 `check_plan` 检查。只有返回 `ok=true` 才能说结构检查通过；不能据此宣称计划可行或任务已经完成。

用户明确要求记住语言、语气或格式时才用 `save_preference`；当前任务的目标和期限不是长期偏好。
